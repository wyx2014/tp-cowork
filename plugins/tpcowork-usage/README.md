# @tpcowork/dsh-usage

连接使用菜单 › **使用统计**，或设置 › 数据与统计 › **使用统计**，按 Zcode「Usage stats › 应用用量」一比一复刻：

- 顶部标题旁的「应用用量」标签；
- 累计摘要条：累计 Token 数、峰值 Token 数（单日最高）、最长聊天时长、当前连续天数、最长连续天数；
- Token 活动热力图：最近 52 周，每日 / 每周 / 累计三种视图，悬停显示日期、Token 与消息轮数；
- 时间范围（近 7 日 / 近 30 日）下的每日 Token 趋势图（每个模型一条平滑曲线，最多 6 个模型）和模型用量环形图（超过 6 个模型时合并为「其他模型」）；
- 刷新按钮、加载中与无数据状态。

数据只来自本机会话，不联网。Host 端监听 DSH 的 `session/event`，每条事件追加时就把模型回复的 Token 用量、轮次起止和工具调用折算进该会话的记录，保存在 `DSH_HOME/usage/records.v3.json`；打开页面汇总已保存的记录。该文件只是缓存：记录中缺少的会话（插件启用前或停用期间的会话、记录文件丢失或被另存之后）会从该会话自己的会话日志重建一次，分叉会话跳过从父会话继承的事件，因此只要会话还在，重装或重启都不会丢失统计。已在记录中的会话不再重复读取日志；已删除会话的用量仍保留在统计中。每条记录保存已计入的事件序号（seq），重复到达的事件不会重复计算。

记录文件无法读取、已损坏或版本不兼容时，原文件会改名为 `records.v3.unreadable-<时间>.json` 保留，再从会话日志重新统计；若连改名也失败，本次运行不写入，避免覆盖原文件。被安全软件短暂占用的文件会先重试读取。插件停止时等待最后一次写入完成；页面在内存中保留上次结果，再次打开时立即显示，同时在后台刷新。

统计口径与 Zcode 相同：

- 按调用方时区的本地日期分桶；「近 7 日 / 近 30 日」从当前时刻往前整 7 / 30 天开始；
- 模型取回复消息记录的模型，旧日志回退到请求头中的模型；
- 最长聊天时长是单个会话内已完成轮次时长之和；
- 当前连续天数从今天往回数，今天没有用量即为 0；
- 分叉会话继承的父会话事件不重复计算；进行中的轮次计入轮次数，但不计时长。

图表为纯 SVG 实现，几何参数与 Zcode 的 Recharts 图一致；配色通过主题层注册浅色与深色两套（Zcode 的 Z.ai 主题色）。页面自带标题行，并以 `data-tpcowork-own-title` 让 UI 插件的通用设置标题让位；导航图标由 UI 插件按「使用统计」行替换为柱状图。

## 开发

```sh
node build.mjs              # 生成 lib/
node build.mjs --typecheck  # Host 与 Client 类型检查
npm test                    # 统计与展示单元测试
```

浏览器端验收：在 `deepseek-harness` 目录运行 `node node_modules/vitest/vitest.mjs run --config ../tp-coworkdsh/scripts/tests/usage-stats.config.mjs --configLoader native --cache=false`。
